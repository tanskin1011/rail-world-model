# 카메라 조건 준수 평가 프로토콜

이 문서는 다음 실험의 설계다. 아래 평가를 수행했거나 FD500의 개선을 확인했다는 뜻은 아니다. 현재 공개 근거는 [결과와 한계](RESULTS.md)에 정리한다.

## 평가 질문

1. 같은 초기 이미지에서 Action만 바꾸면 STOP·정속·가속·감속이 구분되는가?
2. 같은 조건에서 FD500이 FD300보다 입력 궤적을 더 잘 따르는가?
3. 이동 반응이 달라져도 선로·시설물의 배치와 형상이 유지되는가?

## 비교 설계

| 항목 | 고정하거나 기록할 내용 |
|---|---|
| 모델 | FD300·FD500의 실제 체크포인트 및 텐서 해시 |
| 이미지 | 이미지 ID·SHA-256·학습 노출 여부·장면/노선 |
| Action | STOP·정속·가속·감속의 파일 해시·FPS·좌표계·단위 |
| Prompt | 동일한 장면 설명, 이동 지시는 Action으로만 부여 |
| 생성 | seed·sampling steps·guidance·shift·해상도·프레임 수 |
| 반복 | 이미지와 seed를 바꿔 반복하고 모든 조합의 결과 보존 |
| 실패 | 생성 오류·정지 불이행·구조 붕괴도 분모에 포함 |

먼저 작은 장면 집합으로 입출력과 채점 절차를 확인한 뒤 평가 집합을 확정한다. 새 노선 일반화 평가는 노선·원천 영상·합성 맵 단위로 학습 노출을 확인한다. 같은 맵의 다른 프레임만 분리한 결과를 새 환경 일반화로 부르지 않는다.

## 측정 항목

| 항목 | 측정 방법 | 해석상 주의 |
|---|---|---|
| STOP 준수 | 정적인 배경 영역에서 프레임 간 이동량과 누적 drift 측정 | 사람·수목 움직임, 영상 생성 artifact를 분리. 임계값은 결과를 보기 전에 기준 데이터로 결정 |
| 가감속 반응 | 배경 이동량의 시간별 곡선·전후반 변화와 입력 계획 비교 | 광학 흐름의 픽셀 이동량은 km/h가 아님. 깊이·원근·곡선 구간 영향을 받음 |
| 카메라 경로 일치 | GT가 있는 합성 장면에서 동일 기준의 pose 추정·정합 오차 | 추정 실패율도 보고. 단안 scale이 불명확하면 metric 속도·거리를 주장하지 않음 |
| 장면 보존 | 레일·전주·건물의 추적 지속성·형상 변형·객체 소실 채점 | 동일한 rubric으로 판정하고 대표 성공·실패를 함께 공개 |
| 영상 예측 일치 | 동일 초기 이미지·궤적의 GT가 있을 때 PSNR·SSIM·LPIPS 등 | 미래188프레임만 평가. 입력 첫 프레임을 포함해 점수를 높이지 않음 |
| 실행 성능 | 모델 로딩·생성·디코딩 시간, GPU/메모리 환경 | 최초 로딩과 반복 생성 시간을 구분. 실제 측정 전 최소 사양을 단정하지 않음 |

서로 다른 출력이 가능한 실사 장면에서는 픽셀 유사도만으로 옳고 그름을 판정하지 않는다. FVD 등 분포 지표를 추가한다면 클립 수·추출기·전처리를 공개하고, 소수 사례의 점수를 전체 품질로 일반화하지 않는다.

## 결과 공개 형식

실행 한 건당 이미지 ID, Action ID, 모델 해시, seed, prompt, sampling 설정, 출력 해시, 완료/실패 상태를 기록한다. 집계는 모델·조건·장면별 표로 제공한다.

- 유효/실패/제외 수와 제외 사유
- 지표 정의·단위·평가 구간과 실행 코드 버전
- 평균·분산 또는 신뢰구간, 이미지/seed별 원시 결과
- 같은 조건의 짝 비교 영상과 실패 사례
- CPU·GPU 환경, 평가 시간, 필요한 외부 자산

동일한 이미지의 여러 seed를 독립된 새 장면으로 취급하지 않는다. 신뢰구간을 산출할 때는 장면별 반복 구조를 반영한다. 평가 스크립트와 수치 결과는 실험 수행 후 연결한다.
