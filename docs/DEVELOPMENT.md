# 개발 규칙

- 코드, 실행 설정, 실험 결과, 대용량 원본 데이터를 구분한다.
- 새 기능은 CPU 검사부터 만들고 기존 GPU 실행을 임의로 시작하지 않는다.
- 결과 주장의 출처와 측정 범위를 남긴다. 초안의 계획을 완료 사실로 바꾸지 않는다.
- 기존 실험 원본은 변경하지 않는다. 내부 연결은 `internal/`에서 관리한다.
- 공개 가능한 예시는 승인 후 `assets/`에 추가한다. symlink를 따라 내부 자료를 일괄 복사하지 않는다.
- 공개 라이선스는 소유권·기관 승인을 확인한 뒤 정한다.

## 이관 순서

1. 연구 문서와 근거 목록: 1차 완료.
2. CPU 계약 검사와 CI 정의: 로컬 테스트 통과. GitHub CI는 미실행.
3. 프로젝트 고유 학습·추론 코드를 설정 기반으로 분리: 미완료.
4. 기존 모델 추론 CLI: 구현·CPU 검사·단일 GPU end-to-end 재현 확인 완료.
5. 공개 예시 선정과 외부 공개 검토: 미완료.
6. 기존 GitHub 저장소의 개편 브랜치 연결·push 완료. 기존 이력을 보존하고 승인된 코드 변경만 main에 반영한다.
